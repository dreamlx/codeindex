# ADR 005: README_AI.md navigation-contract disclaimer + tighter size cap

## Status

Accepted — 2026-05-25

## Context

codeindex's `README_AI.md` is positioned (per `design-philosophy.md` and `executive-summary.md`) as a **navigation index** that helps agents orient quickly, NOT as authoritative technical documentation. Phase F benchmark (2026-05) tested this contract empirically and found two failure modes against it:

### Failure mode 1: structural bloat

For large directories (e.g. `Application/Common/Business` in a 9977-PHP-file admin codebase, 119 files including 8891-line `OperateGoods.class.php`), codeindex generated a 51KB / 1375-line README containing per-file symbol dumps for all 119 classes — total 1491 symbols listed.

When a sonnet agent was asked to compare two ~4000-line monster files (`Goods` vs `Mgoods`), the WITH-README run used **418K tokens vs 60K without** (+588%). Agent read the full symbol catalog, then followed every breadcrumb across the related classes mentioned in the index, expanding rather than narrowing its search.

### Failure mode 2: semantic over-trust

Across 15 graded question pairs spanning 3 heterogeneous projects (small Python CLI, medium Python pipeline, large legacy PHP):

| | with README | without README |
|---|---|---|
| Avg wall time | -19% | baseline |
| Avg tokens | -28% | baseline |
| Avg correctness | **mixed**: 3 WIN / 9 tie / **3 HURT** | baseline |

The 3 "README HURTS" cases all matched the same pattern: question asked for a precise mechanism, README mentioned the topic in summary form, agent treated the summary as the answer and skipped source verification, producing a wrong answer faster. Worst case (manon `run_mcp.py` sys.path hack): WO = CORRECT, WITH = WRONG.

This validated the design intent's caution — codeindex IS being used as a navigation tool, but agents do not always know to drill further when the navigation index isn't authoritative.

## Decision

Ship two complementary changes; explicitly DO NOT ship a third proposed mitigation.

### Decision 1: Tighten `max_readme_size` default 50KB → 10KB

The 50KB cap allowed a navigation README to grow to roughly the same token cost as reading source directly, defeating the purpose. 10KB forces the index to stay in "summary" territory. Phase F3 spot-test on the 51KB `Common/Business` README: shrinking to 10KB cut WITH-README tokens 65% on the cross-monster question with NO quality drop (both WITH variants graded PARTIAL — neither got it fully right, but the smaller README didn't make it worse).

Sites changed (4): `DEFAULT_INDEXING` dict, yaml template comment, `IndexingConfig` dataclass default, `from_dict` fallback. Commit `1e1a754`. Docs and examples updated.

### Decision 2: Prepend navigation-contract disclaimer to every README_AI.md

```
<!-- codeindex navigation index — agent: drill into source via Read/Grep
     for precise mechanism; do not treat this as final word. -->
```

Inserted as HTML comment at line 0 of every generated README, ahead of the existing `<!-- Generated by codeindex ... -->` line. Defined once as `NAVIGATION_DISCLAIMER` constant in `src/codeindex/writers/__init__.py`, used by 5 generation sites (3 writers, `hierarchical.py`, `writer.py` base + fallback). Commit `f270787`.

Validation: Phase J 3-way experiment on the 3 known-failure questions from F1. The strongest single failure (manon q1, WO=CORRECT/WITH=WRONG in F1) **flipped back to WITH=CORRECT** with disclaimer present. Other 2 questions had high variance (q3) or stayed CORRECT (ds q4), but no question got worse.

### Decision 3: Do NOT ship a CLAUDE.md tool-selection guide (proposed #3)

Considered injecting a per-task tool-selection table (`use README for "what does X do" / use Grep for "find string X" / drill source for "how does X work" / ...`) either via the project's CLAUDE.md or via `--append-system-prompt` at agent invocation.

Phase J 3-way experiment tested this as the `guide` variant against the same 3 questions:

| variant | avg correctness | avg sec | avg tokens |
|---|---|---|---|
| no README (baseline) | 0.83 | 36s | 138K |
| disclaimer only | **0.83** | 30s | 85K |
| disclaimer + guide | **0.67** | 32s | 109K |

The guide variant **hurt average quality** (manon q1 went CORRECT → PARTIAL — agent followed the guide's "drill into source" instruction and over-engineered its search, lost focus). Disclaimer alone matched the WO baseline on quality while saving time and tokens; adding the guide on top regressed.

Hypothesis: a tool-selection table reads as instructive for a confused human; for a competent sonnet agent it acts as over-constraint / noise. The disclaimer is sufficient because it tells the agent the contract (a navigation index, not authoritative) without prescribing process.

## Consequences

### Immediate

- Users with no explicit `max_readme_size` in their `.codeindex.yaml` will see significantly smaller READMEs on next `scan-all`. Per-file structural detail is preserved but bounded. No breaking change — markdown structure unchanged, downstream `cli_symbols.py` Purpose-section parser unaffected.
- Every new README header gains the disclaimer line. Renderers ignore the HTML comment so human-facing markdown is visually unchanged. Agents reading raw markdown see the contract.
- Users with the bundled post-commit hook see both changes flow into their next commit cycle automatically.

### Long-term

- Disclaimer wording is hand-tuned, not A/B-validated. If future benchmarks show diminishing effect or specific failure pattern returns, the disclaimer string is the lever to adjust (single constant in `writers/__init__.py`).
- If users override `max_readme_size` upward, document the tradeoff: larger READMEs increase per-question token cost AND raise the risk of agent over-trust. The current `examples/.codeindex.yaml` comment names the tradeoff.
- The CLAUDE.md tool-selection guide remains an option for individual users who maintain CLAUDE.md aggressively, but is NOT shipped as a default codeindex artifact. Marked do-not-ship until evidence changes.
